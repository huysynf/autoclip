# Internationalization Configuration Guide

This document describes the international configuration and multi-language support of the AutoClip project.

## 📋 Language support

### Currently supported languages
- 🇨🇳 **Chinese** (Simplified) - Main language
- 🇺🇸 **English** - English version

### File structure
```
docs/
├── i18n.md              # 国际化配置指南
├── README-CN.md         # 中文版README（完整版）
└── README-EN.md         # 英文版README

.github/
└── README.md            # GitHub首页展示（简化版）

README.md                # 中文版README（完整版）
README-EN.md             # 英文版README
```

## 🔧 Configuration instructions

### Language switching
A language switching link is included in every README file:
```markdown
**语言**: [English](README-EN.md) | [中文](README.md)
```

### Contact information internationalization
Contact information remains consistent across different language versions to ensure that users around the world can receive support.

## 📝 Content synchronization

### Update process
1. Update Chinese version README.md
2. Synchronously update the English version of README-EN.md
3. Update the GitHub homepage display document
4. Make sure all links and contact details are correct

### Translation Principles
- **Accuracy**: Ensure accurate translation of technical terms
- **Consistency**: Maintain consistency in terminology translations
- **Localization**: Consider the usage habits of users in different languages
- **Completeness**: Make sure all functions have corresponding descriptions

## 🌐 Internationalization best practices

### 1. Technical terms
- Keep the original English text: API, Docker, Redis, etc.
- Chinese translation: database, cache, container, etc.
- Mixed use: Docker containers, Redis cache, etc.

### 2. Code example
- Keep the code the same
- Comments use the corresponding language
- Keep variable names in English

### 3. Links and Contact Information
- Keep the link intact
- Use English for contact information (email, GitHub, etc.)
- Community groups use corresponding platforms

### 4. Pictures and Badges
- Use common icons and badges
- Avoid images containing text
- Use SVG format to ensure clarity
